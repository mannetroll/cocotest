## Automated Data Testing with the Semantic Layer

Build an end-to-end example that creates a semantic view on TPC-H sample data, adds verified queries (VQRs) as "test assertions", and validates them automatically.

### Implementation Steps

1. **Create a schema** in `SNOWFLAKE_LEARNING_DB` for our semantic view and test artifacts

2. **Create a semantic view** (`TPCH_REVENUE_SV`) on `SNOWFLAKE_SAMPLE_DATA.TPCH_SF1` covering:
   - Facts: ORDERS, LINEITEM
   - Dimensions: CUSTOMER, NATION, REGION
   - Metrics: `total_revenue`, `order_count`, `avg_order_value`
   - Named filters: `high_value_orders`, `recent_orders`

3. **Add verified queries (VQRs)** as test assertions — these are known-good SQL that Cortex Analyst must reproduce:
   - "Revenue by region" → expected SQL
   - "Top 10 customers by spend" → expected SQL
   - "Average order value by market segment" → expected SQL

4. **Validate VQRs compile** using `SYSTEM$CORTEX_ANALYST_SVA_TOOL('validate_verified_queries', ...)` — this checks all VQR SQL is syntactically valid against the real schema

5. **Run Cortex Analyst evaluation** — ask natural language questions and verify the generated SQL matches the verified queries (sql_correctness metric)

6. **Wrap in a stored procedure** (`TEST_SEMANTIC_LAYER`) that:
   - Validates all VQRs compile
   - Runs each test question through Cortex Analyst
   - Compares results against expected outputs
   - Returns a pass/fail report

7. **Schedule with a Task** (optional) to run daily as a regression suite

### What This Demonstrates
- Semantic views as a "contract" for your data
- VQRs as executable test cases
- Automated validation that the semantic layer still produces correct SQL
- Regression detection when underlying tables change
